fix: the agent must not reach into the retrieval internals

Introducing the identifier-only query (the broaden-retry's second half) made
apps/api/agent/stoplist.py import apps.api.retrieval.normalizer directly.

architecture.md sec 2 and SPEC.md sec 2 bound the agent's imports to
"retrieval.api (tool impls ONLY)" plus the retrieval Context Builder. The
normalizer is a retrieval INTERNAL - the same class the generation layer is
barred from - so the import was a contract violation, even though the
quarantine script does not catch it (it checks for vector libraries and the
agent-thinness set, not the import surface).

The identifier query now lives on the sanctioned surface:
apps/api/retrieval/api.py gains identifier_labels(), which returns the
canonical labels a query carries, and the agent calls that.

Added test_agent_imports_only_the_sanctioned_retrieval_surface, which pins
the import surface so a future reach into retrieval internals fails the
suite rather than passing unnoticed. Proven to discriminate: with the
normalizer import restored, the test fails with "stoplist.py imports
apps.api.retrieval.normalizer; the agent may import only
['apps.api.retrieval.api', 'apps.api.retrieval.context']".
