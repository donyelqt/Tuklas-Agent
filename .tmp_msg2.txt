test: make the gitleaks step stubs executable

The stubs the gitleaks step test puts on the PATH were written without
the execute bit, so on a Linux runner the shell found the REAL `curl` and
`gitleaks` on the PATH instead and the test exercised the real release
over the network rather than the stubs. The failure it produced named
the wrong thing entirely: the step reported the real release's
checksum, and the assertion that the missing archive be named failed
on empty output.

A file written on Windows carries no execute bit, and `write_text` does
not add one, so the bit is now set explicitly on the three stubs.
